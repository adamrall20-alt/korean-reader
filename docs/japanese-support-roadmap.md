# Japanese support roadmap

## Release goal

Add Japanese to the existing Chrome extension. The same penguin interface should let you click a word in Japanese YouTube subtitles, a transcript or a webpage, choose its definitions, and mine the sentence. Japanese cards go to a separately configured deck. Japanese known words, pending cards and statistics have their own totals. Existing installations open in Korean with their current data and Anki setup.

Use a **Korean / Japanese** selector in the toolbar, with a remembered default and a per-tab reading choice. Show the active language and destination before syncing. Settings and Statistics let you switch between the two languages. Keep the extension name, theme, subtitle appearance controls and explicit **Mine Word** and **Sync to Anki** actions. Release Japanese support once both languages pass the parity checks below.

## Dictionary and Japanese text analysis

| [JMdict English examples release](https://github.com/scriptin/jmdict-simplified/releases) and [Jitendex's source credits](https://jitendex.org/pages/legal.html) | Evaluate the examples-enabled JMdict release for sentence examples. | [KANJIDIC2](https://www.edrdg.org/wiki/index.php/KANJIDIC_Project) | Show available kanji readings and meanings for the word's characters, the Japanese counterpart to the Korean popup's Hanja area. | Use the needed reading and meaning fields. Some other fields have separate terms under the EDRDG licence. |
| [Japanese Wiktionary extraction from Kaikki](https://kaikki.org/jawiktionary/index.html) | Candidate for optional Japanese definitions in the existing definition-language UI. Use Chrome's Translator API for Japanese → English when a Japanese-only entry is available and the browser supports the pair. | Verify coverage, entry-level attribution, licence terms and storage size before distribution. JMdict supplies English glosses. Chrome's translation feature depends on availability and may require a language-pack download. [Chrome Translator API](https://developer.chrome.com/docs/ai/translator-api) |
| [JMnedict JSON](https://github.com/scriptin/jmdict-simplified) | Add a labelled proper-name fallback if subtitle testing shows enough missed names to justify it. | Keep name matches separate from vocabulary coverage by default and confirm current data terms before shipping it. |

Japanese needs its own word analyser because it usually has no spaces between words. The current prototype uses Chrome’s `Intl.Segmenter` for boundaries, then checks word spans and inflections against JMdict parts of speech. This avoids a second tokenizer data download while lookup quality is evaluated. Benchmark against real subtitles before choosing the final analyser. [Kuromoji.js with IPADIC](https://github.com/takuyaa/kuromoji.js) and [Lindera WASM](https://lindera.github.io/lindera/) remain candidates.

For example, one click on `食べなかった` in `昨日はラーメンを食べなかった。` should show `食べる`, reading `たべる`, and the available English meanings. The mined card keeps the full sentence and highlights `食べなかった`. Particles such as `は` and `を` are excluded from unknown-word counts. Match verified kana and kanji variants when they refer to the same entry, and let the user choose when the spelling is ambiguous, such as `生物` (`せいぶつ` or `なまもの`).

## Phase 1 — Language routing and safe storage

- [x] Accept `ko` and `ja` in reading, lookup, mining and vocabulary messages. Keep omitted language compatible with Korean. Gate Japanese analysis and dictionary lookup pending Phase 2.
- [x] Add Japanese vocabulary and history stores in IndexedDB version 5. Keep the existing Korean stores and history keys. Store Japanese dictionary identity, reading, aliases, selected definitions, surface text and click span. Publish language-scoped known-word revisions.
- [x] Add separate Anki profiles for deck, note type and field mappings with one local connection. Keep current settings as Korean. Show the Korean destination and gate Japanese reading in the toolbar. Japanese profile setup supports existing note types.
- [x] Cover the additive upgrade, a synthetic 13,000-word Korean profile, Japanese homographs, span validation, shared connection and concurrent Anki profile saves in automated tests.
- [ ] Verify the upgrade on a real Chrome copy of version 4 data, including Korean counts, chart history, media, unsynced lines and note IDs. Verify concurrent vocabulary edits from two tabs. The isolated Chrome process exited before loading the extension in the development environment.

## Phase 2 — Offline dictionary and lookup

- [x] Import JMdict Simplified locally through Settings. Verify the recommended archive against its published SHA-256 and show the installed release metadata. Build indexes with spelling and reading restrictions in a separate database. Replace the index transactionally and use upstream entry IDs and readings for vocabulary identities.
- [x] Preserve UTF-16 offsets and original text. Use browser segmentation with bounded, part-of-speech-aware matching for common negative, polite, past, passive and contracted forms. Fixtures include kanji, kana, half-width kana, particles and adjacent emoji.
- [x] Reuse the popup from the Settings lookup preview. Show readings, parts of speech, selectable definitions, available examples and alternate matches. The shared mining component carries the chosen lexical identity and original span.
- [ ] Verify import with the full upstream archive in Chrome and measure lookup latency and storage usage on Mac and Windows. Compare the prototype against annotated Japanese subtitles.
- [x] Support optional local Jiten frequency CSV and KANJIDIC2 imports. Show a rank for matching spellings and readings and available readings and meanings for kanji.
- [ ] Evaluate an optional Japanese-only dictionary and its attribution before adding Japanese-to-English machine translation. JMdict already supplies English definitions.

## Phase 3 — YouTube, transcript and webpage parity

- [x] Enable Japanese reading selection when the reader is ready. Persist the default and support a per-tab choice. Invalidate stale lookups and search results when the language changes, restore any previously parsed page, and bind delayed mining and media results to the clicked word's language.
- [x] Update the YouTube overlay, caption monitor, sidebar and transcript bridge to recognize a `ja` track. Prefer a matching manual track when available, then matching auto-generated captions. Use track metadata before script heuristics. Treat kana as a clue when metadata is absent and use explicit Japanese selection for ambiguous kanji-only lines. Preserve native caption fallback and prevent mismatched tracks from feeding the Japanese reader. Handle rolling captions and invalidate stale results on language switches and YouTube navigation.
- [x] Preserve the closed-by-default transcript sidebar, raw and normalized search, click-to-seek, follow mode and partial-transcript fallback. Batch Japanese tokenisation for long transcripts. Reuse the coverage UI with the same unique-word calculation, using Japanese dictionary identities so repeated inflections count once. Exclude grammatical particles, auxiliaries and punctuation while keeping lexical compounds usable.
- [x] Keep **Parse Page** opt-in and reversible. Use `lang="ja"` and kana to identify Japanese text and respect explicit language metadata when distinguishing Japanese kanji from Chinese. Preserve author-supplied ruby, exclude `rt`/`rp` annotation text from analysis and keep editable controls untouched. Extract the clicked sentence by offset, including Japanese punctuation with no following space, and preserve the URL. Restore the original text nodes after turning parsing off.
- [x] Reuse YouTube timestamps, screenshots and caption audio. Save the clicked Japanese form and sentence before optional media completes. Use Japanese font fallbacks and `lang="ja"` in the overlay, popup, sidebar, vocabulary and card template. Reuse the existing keyboard and reduced-motion controls.

## Phase 4 — Japanese Anki deck, vocabulary and statistics

- [x] Recommend an existing or newly created **Japanese Mining** deck. Validate that the two deck trees are disjoint so parent-deck statistics and imports stay separate. Ship a **Japanese Reader** default note type with the same fields (`Focus Word`, `Sentence`, `Definition`, `Pronunciation`, `Image`, `Audio`). Put the kana reading in Pronunciation or map it to the user's existing Reading field. Reuse highlight, media attachment and multi-sentence merging. Local mining works with Anki closed, and sync stays explicit.
- [x] Filter Japanese pending counts and writes by the selected profile. Resolve duplicate notes through a Japanese lexical-identity tag and verify candidate notes and cached note IDs against cards in the chosen deck and note type before writing. Scope Anki's add-note duplicate check to the target deck where supported. Test two readings of the same spelling in one deck. If Anki rejects the shared first field, allow that exception only after confirming the two identities differ and repeating the lookup on retries. Ask for a mapping or choice when older untagged notes are ambiguous. Verify same-spelling notes in another deck and notes with cards spread across decks are protected. Keep Korean's existing note matching, with tests that Japanese-managed notes are excluded. [AnkiConnect add-on](https://ankiweb.net/shared/info/2055492159)
- [x] Keep vocabulary search, pagination, definition editing, **Known** toggles, deletion and JSON export language-scoped. Keep legacy v1 JSON imports mapped to Korean. Add a language-labelled Japanese transfer format that preserves readings and lexical identity. Merge imports without replacing mined contexts, media or Anki metadata. Support plain text and preview imports from Anki focus-word fields, using mapped readings to disambiguate. Show unresolved or skipped items when a spelling alone can't identify one entry.
- [x] Show the active language's known-word total, step chart and history table. Show reviews left today, lifetime reviews done, lifetime review time, seven-day due count and deck coverage for that language's selected Anki deck. Reuse the current AnkiConnect requests and check parent/subdeck rollups against Anki. Keep available metrics visible after a partial failure. Verify Japanese queries and known-word imports pass through Japanese normalization. Anki continues to handle card scheduling and [cross-device sync](https://docs.ankiweb.net/syncing.html).

- [ ] Measure Japanese cold startup, warm lookup, long-transcript processing, worker memory, dictionary installation size and production ZIP size. - [ ] Verify in Chrome on Mac and Windows with manual and auto-generated Japanese captions, Japanese-only pages, mixed-language pages and ruby markup. - [x] Update setup, architecture, dictionary attribution and Anki documentation.
- [ ] Record live results and full-archive performance measurements after browser and Anki verification.

## Beyond parity

Inline furigana across pages and subtitles, pitch-accent diagrams, dedicated word audio, a general Yomitan dictionary importer, and manga image OCR can be considered separately. The initial release needs kana readings in the dictionary and cards, along with the existing sentence audio from YouTube.
